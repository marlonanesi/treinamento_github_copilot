Copilot em Múltiplos Papéis

Como alternar personas para maximizar resultados no desenvolvimento

Use personas claras: Dev, Arquiteto, SM, PO, QA, Frontend, Backend, UI/UX - ou Agent Mode para orquestrar

Por que alternar papéis?

  • Refinamentos focados: negócio, técnico, qualidade, UX
  • Entregáveis claros com critérios de aceite explícitos
  • Handoffs previsíveis, menos retrabalho
  • Você não precisa ser o PO ou o UX — basta usar a perspectiva deles pra validar o seu trabalho
  • Agent Mode: orquestra múltiplos papéis de forma autônoma

Backend Developer (API/Domain)

Propósito: Regras de negócio, casos de uso, endpoints, performance.

Entregáveis: Use case, schema, rota, logs, testes unitários.

  • Papel: Dev backend sênior em FastAPI
  • Objetivo: POST /projetos com validações e repositório mockado
  • Regras: Camadas, Pydantic estrito, logs estruturados
  • Done: 90%+ cobertura, 201/400/422 mapeados

Frontend Developer (UI/Integração)

Propósito: Componentes, estados, acessibilidade e integração com API.

Entregáveis: Tela, estados de loading/erro, testes e2e/unit.

  • Papel: Dev frontend React sênior
  • Objetivo: Tela de cadastro com validação e chamada à API
  • Regras: A11y, design tokens, testes RTL, mock de fetch
  • Done: Form funcional, testes passando, empty/error states

Arquiteto de Software

Propósito: Fronteiras, padrões, decisões (ADR) e diagramas.

Entregáveis: C4 (nivel 2 em texto), ADR, guidelines de camadas.

  • Papel: Arquiteto de software
  • Objetivo: Fronteiras domain/app/infra/presentation
  • Regras: Hexagonal, DTOs estáveis, idempotência
  • Done: ADR com trade-offs, diagrama textual, checklist

Product Owner — visão de negócio

Propósito: Validar se a feature entrega valor antes de apresentar ao time.

Quando usar: Dev pergunta "Como PO: isso faz sentido? Algum critério de aceite faltou?"

  • Papel: Product Owner experiente
  • Contexto: [descreva a feature ou fluxo implementado]
  • Perguntas: Valor entregue? Critérios faltando? Riscos?
  • Done: Lista de gaps e sugestões de refinamento

Scrum Master — antecipando riscos

Propósito: Mapear dependências e impedimentos antes de entrar na sprint.

Quando usar: Dev com task complexa: “Como SM, quais riscos e dependências devo levantar?”

  • Papel: Scrum Master experiente
  • Contexto: [descreva a task ou épico]
  • Perguntas: Dependências? Riscos técnicos/negócio? DoD?
  • Done: Riscos mapeados, dependências listadas, DoD sugerido

QA / Tester

Propósito: Estratégia de testes, pirâmide, casos e automação.

Quando usar: Definir cobertura antes de abrir PR ou entrar em staging.

  • Papel: QA sênior
  • Objetivo: Cobrir cadastro de projeto (unit > api > e2e)
  • Regras: Dados sintéticos, contratos estáveis
  • Done: Casos mapeados, automação CI, cobertura definida

UI/UX Designer — revisando o próprio flow

Propósito: Revisar flow antes de entregar ao time de design.

Quando usar: Dev frontend: "Como UX, tem quebra? Heurística violada?"

  • Papel: Designer UI/UX sênior
  • Contexto: [descreva o fluxo ou tela implementada]
  • Perguntas: Quebra? Fluxo triste coberto? Nielsen?
  • Done: Melhorias, gaps de a11y, sugestões de copy

Fluxograma + Mapa do Usuário

Output da persona UX — vira insumo pro próximo prompt.

Formato texto — fácil de converter pra Mermaid ou wireframe.

  • Abrir → Preencher → Validar → Enviar API
  • ↳ erro → Feedback → Corrigir → Reenviar
  • ↳ ok → Toast Sucesso → Navegar Detalhe
  • Mapa: Gerente | Dores: campos confusos | Ganho: feedback rápido

Orquestração de Prompts (Sequência)

Cada saída vira entrada do próximo papel — handoffs claros, menos retrabalho.

  • PO → histórias e critérios de aceite
  • Arquiteto → fronteiras, ADR e diagramas
  • UX → jornada, fluxo e wireframe
  • Backend + Frontend → implementação
  • QA + SM → testes, plano e DoD

Resumo

  • Defina persona, propósito e entregáveis por prompt
  • Encadeie papéis para reduzir retrabalho
  • Não precisa ser o PO, SM ou UX — use a perspectiva deles pra validar seu trabalho
  • Agent Mode = orquestração automática dos papéis
