MCP - Model Context Protocol

Conectando modelos de IA ao mundo real

O problema: LLMs isolados

  • LLMs são poderosos, mas vivem dentro de uma "bolha"
  • Sem acesso nativo a arquivos locais, bancos de dados e APIs externas
  • Cada integração era resolvida de forma diferente e proprietária
  • Resultado: esforço duplicado, integrações frágeis e sem padrão
  • O modelo sabe muito, mas não consegue agir no mundo real sozinho

O que é MCP?

  • Model Context Protocol: protocolo aberto criado pela Anthropic (2024)
  • Padroniza como modelos de IA se conectam a ferramentas e fontes de dados externas
  • Open source, agnóstico de modelo e de linguagem de programação
  • Define uma interface única: um modelo pode usar qualquer ferramenta que fale MCP
  • Elimina integrações ad-hoc e promove reuso entre ferramentas e modelos

Analogia: USB-C para IA

  • Antes do USB-C: cada fabricante tinha seu próprio conector
  • Com USB-C: um padrão único conecta qualquer dispositivo a qualquer acessório
  • MCP é o "USB-C para IA": um protocolo que conecta qualquer modelo a qualquer ferramenta
  • O modelo não precisa saber como a ferramenta funciona internamente
  • A ferramenta não precisa saber qual modelo vai consumi-la

Arquitetura — O triângulo MCP

  • Host: a aplicação que o usuário usa (VS Code + Copilot, Claude Desktop, Cursor)
  • Cliente MCP: componente embutido no Host que fala o protocolo MCP
  • Servidor MCP: processo que expõe ferramentas, recursos e prompts ao modelo
  • O Host inicia a conversa → o Cliente descobre as ferramentas → o modelo as invoca
  • O Servidor executa a ação real (ler arquivo, chamar API, consultar banco)

MCP no ecossistema atual

  • GitHub Copilot: suporte a MCP Servers no VS Code e GitHub.com
  • Claude / Claude Desktop: pioneiro na adoção do protocolo
  • Cursor e Windsurf: IDEs com suporte nativo a servidores MCP
  • Adoção crescente: Microsoft, Google, OpenAI e a comunidade open source
  • Efeito de rede: mais servidores disponíveis → mais valor para qualquer cliente MCP

Tipos de servidores MCP

  • Local (stdio): processo rodando na sua máquina, comunicação via stdin/stdout
  • Ideal para ferramentas de desktop: acesso a arquivos, terminal, banco local
  • Remoto (SSE / HTTP): servidor na nuvem, comunicação via HTTP com Server-Sent Events
  • Ideal para APIs externas, SaaS e integrações compartilhadas em equipe
  • Ambos seguem o mesmo protocolo — o cliente não precisa saber a diferença

Onde encontrar servidores MCP

  • GitHub Marketplace: servidores publicados e verificados pela comunidade
  • mcp.so: diretório centralizado com servidores categorizados por função
  • Repositórios oficiais: Anthropic, GitHub, Microsoft e parceiros publicam servidores de referência
  • Exemplos populares: filesystem, GitHub, Postgres, Slack, Brave Search, Puppeteer
  • Você também pode criar seu próprio servidor MCP com poucos arquivos
